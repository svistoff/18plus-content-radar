# Инструкции для Claude Code в этом репозитории

## Проект

`18plus-content-radar` — контент-завод для 18+ блога (отношения, dating,
интимность, сексология, психология): находит и ранжирует видео на YouTube,
а из выбранного вручную видео готовит редактируемый Content Pack (статья,
карусель, Reels-сценарии, посты VK/Дзен/Telegram, промпты для иллюстраций).
Публикация всегда ручная — система ничего не постит сама.

Это отдельный проект, не связанный с другими ботами на VPS пользователя —
не путать со стеком/правилами деплоя других репозиториев.

## Деплой

В отличие от Supervisor-ботов на этом же VPS, `18plus-content-radar`
разворачивается через **Docker Compose** (см. `docker-compose.yml`) — так
рекомендовано в исходном ТЗ из-за зависимости от PostgreSQL (и позже
Redis/Celery для планировщика). Не смешивать со Supervisor-конфигами других
проектов.

Основные команды:

```bash
docker compose up -d --build
docker compose exec web alembic upgrade head   # появится вместе с Alembic
docker compose logs -f web
```

`.env` не коммитится, в репозитории хранится только `.env.example`.

## Архитектура (по мере роста проекта)

- `app/main.py` — FastAPI-роуты и Jinja2-дэшборд.
- `app/models.py` — SQLAlchemy-модели.
- `app/services/` — интеграции и бизнес-логика (YouTube, транскрипты,
  AI, скоринг) — каждая внешняя система в своём модуле.
- `app/templates/` — HTMX/Jinja2-шаблоны дэшборда.

Этапы реализации идут по плану из ТЗ (Radar → Watchlist/метрики → Topics →
Transcript pipeline → Content Factory → production hardening) — не
забегать вперёд и не тащить сложность следующих этапов в текущий.

## Контентные ограничения (обязательно учитывать в любом коде/промптах)

- Тематика — отношения, dating, интимная жизнь взрослых, сексология,
  психология отношений, семья. НЕ порнография/эротика ради возбуждения.
- Запрет на контент с несовершеннолетними или намёками на них.
- Никаких медицинских/психологических/юридических утверждений без пометки
  на ручную редакторскую проверку.
- AI не должен пересказывать transcript дословно/последовательно — только
  использовать как источник фактов для самостоятельного материала, с
  сохранением ссылки на источник (attribution) в каждой карточке.
