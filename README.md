# 18plus Content Radar

Редакционный контент-завод для блога 18+ тематики (отношения, dating,
интимность, сексология, психология). Система находит и ранжирует видео на
YouTube, а по видео, выбранному вручную, готовит редактируемый Content Pack
(статья, карусель, Reels-сценарии, посты VK/Дзен/Telegram, промпты для
иллюстраций). Публикаций во внешние сервисы система не делает — только
исследует, ранжирует и готовит черновики, решение всегда за редактором.

## Что уже есть

- FastAPI-приложение с локальной/Postgres базой (SQLAlchemy);
- управление поисковыми тематическими запросами (`/queries`);
- реальный поиск видео через **YouTube Data API v3** по кнопке «Искать» у
  каждого запроса — с сохранением/обновлением канала и видео (просмотры,
  превью, дата публикации, длительность);
- список найденных видео (`/videos`);
- Docker-конфигурация для запуска на VPS.

## Что будет добавлено следующим этапом

- watchlist каналов и история метрик (snapshots);
- расчёт Viral Score / Topic Heat / Controversy / Editorial Score;
- transcript pipeline (`youtube-skills`/TranscriptAPI + Whisper fallback);
- AI Editorial Analysis и генерация Content Pack;
- планировщик (Celery/APScheduler) для регулярного автопоиска.

Полное техническое задание — см. историю обсуждения проекта; архитектура и
модель данных здесь следуют ему поэтапно, без забегания вперёд.

## Как получить YOUTUBE_API_KEY (бесплатно)

1. Зайти в [Google Cloud Console](https://console.cloud.google.com/).
2. Создать проект (или использовать существующий).
3. В «APIs & Services → Library» включить **YouTube Data API v3**.
4. В «APIs & Services → Credentials» создать API key.
5. Вставить ключ в `.env` как `YOUTUBE_API_KEY=...`.

Бесплатная квота — 10 000 единиц/день, одного поискового запроса хватает
примерно на 100 таких запусков в день.

## Локальный запуск

1. Скопировать `.env.example` в `.env`, заполнить `YOUTUBE_API_KEY`
   (без него поиск не запустится, остальной интерфейс работает).
2. `docker compose up --build`.
3. Открыть `http://localhost:8000`.

## Деплой на VPS

Проект зависит от PostgreSQL и разворачивается через Docker Compose (см.
`docker-compose.yml`), в отличие от других ботов на этом VPS, которые живут
под Supervisor без Docker — эти подходы не пересекаются и не должны
смешиваться. Подробности — в `CLAUDE.md`.
